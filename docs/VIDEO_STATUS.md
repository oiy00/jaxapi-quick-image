# 视频协议与计费：已核实 / 未应用

本文件是审查材料。没有改 jaxapi.top，没有发出生图或视频请求，没有打开菜单，也没有恢复 `/image` 公网入口。

## 已核实

- SuperGPT 帮助页 `https://console.supergpt.dev/help/api-examples` 和 `https://console.supergpt.dev/help/clients` 只给出 `POST /v1/chat/completions`、`POST /v1/responses`、`POST /v1/messages`。常规 Base URL 是 `https://api.supergpt.dev/v1`。特殊分组要以密钥自己的连接信息为准。文档写明超时不等于上游没处理，重复提交可能再计费。
- 模型广场页面列出了这 17 个视频模型名。那是目录，不是生成协议。
- Sub2API commit `5c2982a81b46e2142d0143d2f83c1ce9c4da1d24` 的 `gateway.go`：`/v1/videos` 与状态、内容路由只放行 Grok 和 Composite。openai 平台返回 404，`Videos API is not supported for this platform`。媒体台分组是 openai 平台，不能把这些路由当成可用入口。
- 同一 commit 的 `video_billing_resolution.go`：计费时长收敛到 1–15 秒，未指定时按 8 秒；分辨率只认 480p、720p、1080p。这表达不了 muse 的 20/30/60 秒、seedance 的 30 秒、768p 或 2k。JL 10 秒和 15 秒同为 6.00 USD，按 0.40 USD/秒会把 10 秒算成 4.00，不能当成售价。

## 未核实，因此没有真实 adapter

每个模型的真实 endpoint、JSON 还是 multipart、同步还是任务、状态枚举、下载方式和有效期、失败是否收费、计费发生在提交还是完成，都没有公开证据。草稿里的 `seconds`、`size`、`2560x1440` 仍是猜测，程序不会发送。768p 按 MiniMax H3 官方 16:9 尺寸写作 `1344x768`（之前误写成 `1366x768`，上游不接受），同样只用于界面显示，不会发送。

在拿到可引用的协议之前，禁止用探测请求补这个缺口。

## 本地模拟账本

`lib/video-ledger.ts` 是可单测的绝对价账本，只供 `/api/mock/videos`：

- 分组必须叫「媒体台」。不读取分组编号，所以不会把 11 写死，也不会误用「ChatGPT 生图」。
- 价格只来自价表。客户端即使传 `clientMultiplier: 0.26` 也不参与计算。
- 同一用户、同一幂等键再次提交返回原任务，只预扣一次。
- 其他用户读取任务得到拒绝，看不到内容。
- 余额不足不建任务。
- 失败和超时各退回一次预扣，再次查询不再退、也不新开任务。
- 完成只把预扣结成一次扣费，再次查询不追加。

这是进程内存。重启后任务消失；页面遇到缺失任务时停止，不会自动重提。它不写 jaxapi 余额。

## 以后要在 Sub2API 里应用、本次没有应用的部分

不要用现有 `CalculateVideoCost` 或 `video_model_prices` 的美元/秒去套这张表。后续补丁需要单独的「按次绝对价」：

1. 只对名为媒体台、且显式打开该计费模式的分组生效。不要全局改 openai 视频路由，不要动 group 7、支付、邮件或 CDK。
2. 价键是模型 ID + 秒数 + 分辨率档，金额等于本仓库价表，单位是美元/次。未列出的组合拒绝，不要折进 15 秒或 480p。
3. 扣费绑定服务端认证用户和任务 ID。不信任浏览器传来的用户编号。上游密钥只留在服务端。
4. 幂等键重复时返回原任务。查询和下载不再扣费。失败、超时是否退款必须跟已核实的上游规则一致；在核实前不能把模拟账本的退款当成上游承诺。
5. 真实提交仍要等视频协议证据。没有证据就不要把 `/v1/videos` 接到媒体台。

这些步骤需要在生产机上由负责人应用。本仓库不包含那次部署。
